# Hy4 Prefill Context Parallel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable fail-closed Hy4 sparse-MLA serving with TP4+PCP2 on eight HCUs, then validate target-only, AITER, MTP1, and MTP2 execution.

**Architecture:** Reuse the existing HCU Model Runner V2 PCP manager, MLA/indexer cache gathers, sampling restoration, and MoE PCP dispatch. Extend the MLA PCP architecture contract to `HYV4ForCausalLM` and opt Hy4's sink-capable sparse implementation into PCP; add no second runner or Hy4-specific collective algorithm unless a failing integration test proves the generic ownership contract insufficient.

**Tech Stack:** Python 3.10, PyTorch, vLLM 0.25.1, vllm-plugin-das, pytest, HCU/BW1100, FlashMLA sparse attention, Triton/AITER MoE, EvalScope.

**Spec:** `docs/superpowers/specs/2026-08-31-hy4-pcp-design.md`

## Global Constraints

- The validation host has eight HCUs; the supported topology is exactly TP4+PCP2, not TP8+PCP2.
- PCP requires Model Runner V2, MLA, expert parallelism, eager execution, and PP/DP/DCP sizes equal to one.
- PCP supports target-only decoding or built-in MTP with one or two speculative tokens; MTP3 stays rejected.
- Graph support, LoRA, KV offload, P/D disaggregation, lightly-CP, multimodal PCP, and HCU multi-layer MTP are outside this implementation.
- The first integration stage uses Triton MoE; AITER is enabled only after target-only PCP correctness is established.
- Preserve all PCP=1 behavior and all existing GLM-5.2/GQA PCP contracts.
- Every production behavior change requires a test that was observed failing first.
- Do not stage or modify `docs/superpowers/plans/2026-08-30-hy4-aiter-mtp-accuracy-investigation.md`; it is user-owned and untracked.
