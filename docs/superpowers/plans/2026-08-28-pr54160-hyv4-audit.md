> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Determine which correctness fixes from vLLM PR #54160 apply to the v0.25.1 HCU HYV4 port, make only evidence-backed compatibility fixes, and validate the block-wise MXFP8 model.

**Architecture:** Compare each upstream HYV4 correctness commit with the equivalent HCU model, attention, quantization, and worker-runtime path. Keep v0.25.1-specific implementations when newer-main APIs are unavailable, and validate equivalent behavior with focused unit tests plus concurrent TP8 inference.

**Tech Stack:** Python 3.10, vLLM 0.25.1, PyTorch/ROCm, HCU plugin, pytest, OpenAI-compatible HTTP API.

**Spec:** [vLLM PR #54160](https://github.com/vllm-project/vllm/pull/54160)

## Global Constraints

- Preserve all pre-existing dirty-worktree changes.
- Do not port HYV4 MTP support; the v0.25.1 plugin intentionally registers the backbone only.
- Do not use main-branch APIs that vLLM 0.25.1 does not expose.
- Validate `/models/Hy4-preview-FP8-Testing` with TP8 and runtime MXFP8 dequantization.
- Do not report the five-sample HumanEval score as a formal 164-sample score.
