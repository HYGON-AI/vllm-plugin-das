# GLM-5.2 HCU Prefill Context Parallel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add plugin-owned Model Runner V2 PCP support for `/models/GLM-5___1-Channel-FP8-w8a8`, accepting the eight-HCU topology `TP=4 + PCP=2 + EP` in eager mode without modifying vLLM v0.25.1.

**Architecture:** Selectively backport vLLM PR #46570 into the HCU plugin. A fail-closed config adapter enables only the approved MLA PCP scope; `HcuPCPManager` partitions global MRV2 batches into DualChunkSwap virtual rows and restores them before sampling; exact-name adapters make KV ownership DCP-only and gather MLA/indexer cache inputs; the plugin-owned MoE runner performs one PCP dispatch/combine path. Every PCP branch is conditional on `prefill_context_parallel_size > 1`, so PCP=1 keeps the existing runtime.

**Tech Stack:** Python 3, vLLM v0.25.1, PyTorch distributed, HCU FlashMLA/sparse MLA, Triton MoE, pytest, EvalScope.

**Spec:** `docs/superpowers/specs/2026-08-19-glm52-pcp-hcu-design.md`

## Global Constraints

- Change only `/models/zb/vllm_025_hcu/vllm-plugin-das`; do not edit or commit `/models/zb/vllm_025/vllm`.
- Target exactly vLLM v0.25.1 and validate every runtime-patch symbol and signature before installation.
- Support MRV2, MLA/sparse MLA, PP=1, DCP=1, DP=1, eager execution, and EP. Reject V1, PP, DCP, DP, speculative decoding/MTP, graphs, LoRA, multimodal input, KV offload, P/D disaggregation, and HCU lightly-CP.
- Keep `--prefill-context-parallel-size` as the only PCP flag. PCP=1 must not construct a manager, change cache sizing, invoke a PCP collective, or change MoE routing.
- PCP partitions prefill work but does not shard KV ownership. DCP alone controls KV block sizes, slot ownership, and per-rank KV capacity.
- Preserve Apache-2.0 notices and name vLLM PR #46570 / commit `b6ff8a2f50` in upstream-derived modules.
- Acceptance topology is eight HCU devices: baseline `TP=8, PCP=1, EP`; candidate `TP=4, PCP=2, EP`; both MRV2, eager, `--moe-backend triton`, deterministic sampling.
