# Hy4 DCP on v0.28.1-dev: Design

## Purpose and baseline

Add a separately gated decode context parallel (DCP) Hy4 path to the new
stacked follow-up MR based on PR #152 commit `1b51a2b`. The v0.25.1 Hy4
PCP records explicitly used DCP1; they do not establish a Hy4 DCP2 accuracy
baseline. DCP2 is therefore a new capability, not a claim of old-version
parity. The existing PR #152 TP8/DP8 non-DCP gates remain regression controls.

The installed target vLLM's sparse FlashMLA implementation rejects BF16 KV
when DCP must return per-token LSE; its validated DCP path is FP8 mixed-batch
with the `ag_rs` communicator and compatible local/gathered head padding.
For this checkpoint, 64 attention heads at TP8 give 8 local and 16
DCP-gathered heads: both enter the same FP8 kernel padding envelope. The Hy4
sink implementation inherits target vLLM's `FlashMLASparseImpl` directly; it
does not use the separate generic HCU sparse implementation's FP8+DCP
rejection. These are source-level feasibility facts, not a live accuracy gate.

## First supported topology

Validate `/models/Hy4-preview-Channel-FP8-w8a8-v2` on eight HCUs with
TP8/DCP2/EP8/PP1/PCP1/DP1, Model Runner V2 and sparse FlashMLA. DCP is a
subgroup of TP here; it does not multiply the world size. Begin with
target-only native FP8 E4M3 KV, then MTP3 with the same KV dtype. Use the default
non-eager Graph policy only after an eager diagnostic establishes the
attention/cache path. No DCP+PCP, PP, DP, LoRA, P/D disaggregation or
multi-layer speculative route is claimed. Unsupported combinations must
fail before weight loading. BF16 KV with DCP is explicitly outside this MR:
the installed target vLLM rejects it at sparse FlashMLA initialization, so
support would require a separately reviewed target-vLLM change and paired
wheel rather than relaxing the plugin's topology guard.

The implementation must not silently lower TP, disable MTP, switch to an
unrequested attention/MoE backend or force eager to report the default-Graph
gate as passing. If TP8/DCP2 exceeds the actual eight-card memory budget or
the pinned vLLM rejects the graph contract, record that as an explicit
blocker; do not pick a different topology and call it equivalent.

## Runtime design

1. Replace the blanket Hy4 DCP rejection with a model-specific, topology-
   checked DCP2 branch. Preserve the existing DCP1 path exactly. Reuse the
   current official MLA DCP metadata, cache interleave and all-gather/LSE
   merge contracts; do not fork the full attention implementation.
2. Confirm the HCU sink-capable sparse FlashMLA kernel returns output and
   per-head LSE for DCP. Each rank consumes its local cache share and the
   official DCP combine reconstructs the global softmax result. Short
   prefill still uses sparse MQA so the learnable sink is applied on every
   token; a dense sink-less fallback is not acceptable. Keep target vLLM's
   FP8 mixed-batch index filtering and empty-row identity.

   DCP all-gathers 8 local query heads into 16, so gather the corresponding
   loaded per-head sink weights in the same rank order once after weight
   loading; do not use the local 8-element sink against a 16-head query.
   FlashMLA's `attn_sink` scales output but explicitly leaves returned LSE
   unchanged. Apply the gathered sink only on DCP rank 0, and after the
   inherited mixed-batch path neutralizes empty KV rows, replace rank 0's
   raw LSE with `logaddexp(raw_lse, sink)`; other ranks keep their raw LSE.
   This gives the official DCP combine exactly one sink term in the global
   denominator. A rank-0 empty KV row retains zero output but has LSE equal
   to the sink logit; an empty row on any other rank remains `(0, -inf)`.
   DCP1 retains its existing sink kernel behavior and LSE shape.

3. Keep query projection sharding consistent with the current vLLM TP/DCP
   contract. `VLLM_DCP_Q_REPLICATE` remains opt-in and disabled for the first
   gate; enabling it requires its own weight-loader, local-view, graph and
   numerical tests. Do not port legacy loader assumptions merely because
   the adapter class exists.
4. Preserve official KV allocation and the HCU native cache writer. Verify
   DCP slot mapping, virtual block/interleave arithmetic and sparse-indexer
   cache reader/writer agreement for FP8 E4M3. Do not substitute
   an AITER writer or change the scheduler page to repair a kernel mismatch.
5. Keep DP/EP and MTP ownership independent from DCP. MTP metadata rebuild,
   target verification and draft acceptance must remain correct in mixed
   continuous batches; graph capture alone is not evidence of accuracy.

## Alternatives considered

Removing the guard and relying on existing partial DCP code is fast but
unsafe: it proves neither sink/LSE reduction nor cache and indexer ownership.
Copying v0.25.1 MLA/runner code would fight the current official owner and
has no Hy4 DCP accuracy reference. Extending BF16 DCP now would change the
target vLLM sparse FlashMLA contract and require a paired vLLM wheel, so it
is deferred. The narrow current-ABI FP8 adapter with fail-closed tests is
preferred.

## Verification and release boundary

Write failing source tests before enabling DCP: valid TP8/DCP2 acceptance,
nearby invalid topology and BF16+DCP rejection, query shard/load, FP8 sink +
LSE combine (including rank-0 empty KV rows and sink counted once), cache
slot/interleave/indexer contracts, MTP metadata, and DCP1 regression. Assert
the target FP8 mixed-batch preconditions (`ag_rs`, 8 local
heads and 16 gathered heads in one padding envelope) before loading weights.
Run changed test files, Hy4 and DCP suites, and the repository suite;
document every failure. Establish an eight-card no-DCP control with identical
model/evaluation settings and FP8 E4M3 KV, then run DCP2 target-only and MTP3.
Require default-Graph target/draft capture, concurrent mixed requests,
HumanEval/0–7 functional smoke and a 32-sample accuracy gate against the
no-DCP control. Retain raw completions, finish reasons, scores, logs,
selected kernels and draft acceptance. A service that starts or accepts
drafts but changes correctness has not passed. Build an isolated plugin
wheel from a clean commit and record the paired target vLLM provenance.
Publish only the verified DCP scope in the new MR; leave it Draft if the
32-sample or paired-wheel gate remains incomplete. Update the local upgrade
skill after the final evidence is collected.
